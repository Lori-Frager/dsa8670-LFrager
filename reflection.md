## Reflection

One thing I learned on GitHub is that everything must be approved before it is added to the repository.  I actually like that, so I, or down the road, a team member doesn’t accidentally overwrite code, results or general information in the project.   It keeps track of everything, even when you make a mistake.  Which is good.  You can go back and learn from the mistakes, what worked and what didn’t work and then move forward.


The challenging part is going through the different steps. I want to make sure I do them in order, but it looks like if you still need to push or pull a change, you can always come back to that step if it was missed.  It will just be sitting there for you to do something with it. 


Working through the desktop method, you are actually working in the folder where the files are located and editing the actual files. Then, when creating a new file in that same folder,  the file will appear in GitHub Desktop.  It took me a little while to wrap my head around this process.  I basically just had to try it to make sure it worked.


Having the files on your computer, no one will overwrite your information without approval. I like that we can see and review the changes, especially the way it highlights the red and green comparisons, making it easy to see which lines have been changed and what has been updated.  


I do have a couple of questions.  If we all have a repository on our computer, do we all (each of us) have to accept the changes being made by another team member?  If one person accepts the pull, will all our desktop versions update?
